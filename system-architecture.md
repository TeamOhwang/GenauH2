# GenauH2 시스템 아키텍처 (우분투 배포)

## 전체 시스템 개요

GenauH2는 수소 발전소 모니터링 및 관리 시스템으로, 프론트엔드(React), 백엔드(Spring Boot), 데이터 처리(Python), 그리고 다양한 데이터베이스와 외부 서비스를 통합한 마이크로서비스 아키텍처를 채택하고 있습니다.

## 우분투 서버 구성

### 1. 서버 사양 권장사항
```
- CPU: 4코어 이상 (Intel i5/AMD Ryzen 5급)
- RAM: 8GB 이상 (16GB 권장)
- Storage: 100GB 이상 SSD
- OS: Ubuntu 22.04 LTS
- Network: 1Gbps 이상
```

### 2. 서버 구성 요소

#### 2.1 시스템 서비스
- **Nginx**: 웹 서버 및 리버스 프록시
- **MySQL**: 메인 데이터베이스
- **Redis**: 캐시 및 세션 저장소
- **Java 17**: Spring Boot 실행 환경
- **Python 3.10+**: Flask 서비스 실행 환경
- **Node.js 18+**: React 빌드 및 개발 서버

#### 2.2 보안 구성
- **UFW**: 방화벽 설정
- **SSL/TLS**: Let's Encrypt 인증서
- **Fail2ban**: 침입 방지 시스템
- **JWT**: API 인증/인가

#### 2.3 모니터링 및 로깅
- **systemd**: 서비스 관리
- **logrotate**: 로그 파일 관리
- **Prometheus + Grafana**: 시스템 모니터링 (선택사항)

## 배포 아키텍처

### 1. 프로덕션 환경 구성

```
우분투 서버 (22.04 LTS)
├── Nginx (포트 80, 443)
│   ├── 프론트엔드 정적 파일 서빙
│   ├── 백엔드 API 프록시 (/api/*)
│   ├── Python 서비스 프록시 (/telemetry/*)
│   └── WebSocket 프록시 (/ws/*)
├── Spring Boot 애플리케이션 (포트 8080)
│   ├── REST API 서비스
│   ├── WebSocket 서버

## 성능 최적화

### 1. 애플리케이션 레벨
- **Spring Boot**: JVM 튜닝, 커넥션 풀 최적화
- **React**: 코드 스플리팅, 지연 로딩, CDN 활용
- **Python**: Gunicorn + uWSGI, 비동기 처리

### 2. 데이터베이스 레벨
- **MySQL**: 인덱스 최적화, 쿼리 튜닝, 커넥션 풀
- **Redis**: 메모리 최적화, 지속성 설정

### 3. 인프라 레벨
- **Nginx**: 정적 파일 캐싱, gzip 압축, 로드 밸런싱
- **시스템**: 스왑 설정, 파일 디스크립터 제한

## 확장성 고려사항

### 1. 수평 확장
- **로드 밸런서**: HAProxy 또는 Nginx Plus
- **데이터베이스**: MySQL Master-Slave 복제
- **Redis**: Redis Cluster 또는 Sentinel

### 2. 수직 확장
- **서버 리소스**: CPU, RAM, Storage 업그레이드
- **네트워크**: 대역폭 증가

### 3. 마이크로서비스 분리
- **API Gateway**: Spring Cloud Gateway
- **서비스 디스커버리**: Eureka 또는 Consul
- **설정 관리**: Spring Cloud Config

## 백업 및 복구 전략

### 1. 데이터베이스 백업
- **MySQL**: mysqldump + binlog
- **Redis**: RDB + AOF
- **자동화**: cron + 스크립트

### 2. 애플리케이션 백업
- **JAR 파일**: 버전 관리
- **설정 파일**: Git 저장소
- **로그 파일**: 로그 로테이션

### 3. 재해 복구
- **RTO**: 4시간 이내
- **RPO**: 1시간 이내
- **백업 테스트**: 월 1회

## 모니터링 및 알림

### 1. 시스템 모니터링
- **리소스 사용률**: CPU, RAM, Disk, Network
- **서비스 상태**: systemd 서비스 모니터링
- **로그 모니터링**: 에러 로그 추적

### 2. 애플리케이션 모니터링
- **Spring Boot Actuator**: 헬스 체크, 메트릭
- **Custom Metrics**: 비즈니스 로직 모니터링
- **APM**: Application Performance Monitoring

### 3. 알림 시스템
- **이메일 알림**: 시스템 이슈, 에러 발생
- **SMS 알림**: 긴급 상황
- **웹훅**: 외부 시스템 연동

이 아키텍처는 GenauH2 시스템의 현재 구조를 기반으로 하며, 우분투 환경에서의 안정적인 운영과 확장성을 고려하여 설계되었습니다.
